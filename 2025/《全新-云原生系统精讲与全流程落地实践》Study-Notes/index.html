云原生 VS 云计算

云计算

云计算定义

  • 云计算（cloud computing），一种基于互联网的计算方式，通过这种方式，共享的软硬件资源，可以按需求提供给计算机各种终端和其他设备，使用服务商提供的电脑基建作计算和资源。

云计算本质

把大量机器整合成一个虚拟的超级机器，给分布在世界各地的人们使用，也就是公共计算服务

云计算的发展历程

云计算的分层设计

  • 云计算的三种主要服务模式，各自侧重不同的层面

云原生

概述

  • 云原生是在云计算的基础上发展，云原生是云计算Pass平台解决方案之一

  • 云原生是基于云计算的架构模式，强调微服务、容器化和动态管理，以实现灵活、可扩展的应用交付。作为PaaS平台的解决方案，云原生利用自动化和弹性特性，使开发者能够快速构建、部署和管理应用程序。通过容器编排（如Kubernetes），云原生平台优化资源利用，提高开发效率，支持持续集成和交付，最终推动企业在快速变化的市场中保持竞争力。

CNCF

  • Cloud Native Definition（CNCF定义的云原生）

Cloud native technologies empower organizations to build and run scalable applications in modern, dynamic environments such as public, private, and hybrid clouds.

云原生技术使组织能够在现代动态环境中（例如公有云、私有云和混合云）构建和运行可扩展的应用程序。

Containers, service meshes, microservices, immutable infrastructure, and declarative APIs exemplify this approach.

容器、服务网格、微服务、不可变基础设施以及声明式 API 体现了这种方式。

These techniques enable loosely coupled systems that are resilient, manageable, and observable.

这些技术可以实现松耦合的系统，使其具有弹性、可管理性和可观测性。

Combined with robust automation, they allow engineers to make high-impact changes frequently and predictably with minimal toil.

结合强大的自动化，它们使工程师能够以最少的重复劳动，频繁并可预测地进行高影响的变更。

  • CNCF与云原生

云原生与云原生计算基金会（CNCF）之间有着密切的联系。云原生是一种开发和运行应用程序的模式，强调使用容器化、微服务、持续交付和弹性架构等技术，以实现快速迭代和高可用性。CNCF成立的目的是促进云原生技术的发展和普及，支持开源项目的生态系统。

CNCF托管了一系列关键的开源项目，如Kubernetes、Prometheus和Envoy，这些项目在云原生架构中扮演着重要角色。Kubernetes作为容器编排工具，帮助开发者管理容器化应用的部署和伸缩；Prometheus提供监控和警报功能，确保应用的健康运行；而Envoy则用于服务间的通信和流量管理。

CNCF通过推动这些项目的标准化和互操作性，促进了云原生技术的成熟，使得企业能够更加高效地采用云原生方法论。通过加入CNCF，企业和开发者能够获取最新的云原生技术和最佳实践，推动自身的数字化转型。总之，云原生为应用开发提供了新范式，而CNCF则是这一领域的核心推动者。

CNCF孵化了一系列的云原生项目：https://landscape.cncf.io/

云原生应用程序技术特点

  • 概述

    • 云原生应用程序是由多个称为微服务的相互依赖的小型服务组成的软件程序。
    • 传统上：开发人员使用包含所有必需功能的单块结构构建整体式应用程序
    • 使用云原生方法：软件开发人员将功能分解为更小的微服务。这使得云原生应用程序更加敏捷，因为这些微服务可以独立工作，并且只需极少的计算资源即可运行

  • 云原生应用程序 VS 传统企业应用程序

    • 传统：传统的企业应用程序是使用不太灵活的软件开发方法构建的。开发人员通常在发布大量软件功能以供测试之前进行工作。因此，传统的企业应用程序需要更长的部署时间，而且无法扩展。
    • 云原生：云原生应用程序使用协作方法，并且在不同平台上具有高度可扩展性。开发人员使用软件工具在云原生应用程序中大幅度实现构建、测试和部署过程的自动化。您可以立即设置、部署或复制微服务，这是传统应用程序无法实现的操作。

  • CNCF总结的云原生五大特性

    • 容器

      • 容器化是一种软件部署流程，可将应用程序的代码与应用程序在任何基础设施上运行所需的所有文件和库进行捆绑。通常，要在计算机上运行任何应用程序，必须安装与计算机操作系统匹配的应用程序版本。例如，您需要在 Windows 计算机上安装 Windows 版本的软件包。但是，借助容器化，您可以创建能够在所有类型的设备和操作系统上运行的单个软件包或容器

    • 不可变基础设施

      • 不可变基础设施意味着用于托管云原生应用程序的服务器在部署后保持不变。如果应用程序需要更多计算资源，则会丢弃旧服务器，并将应用程序移至新的高性能服务器。通过避免手动升级，不可变基础设施使云原生部署成为一个可预测的过程。

    • 声明式 API

      • 用户只需要描述期望状态，由系统负责将实际状态转为期望状态，用户无需关心系统怎么实现

    • 微服务

      • 微服务是小型的独立软件组件，它们作为完整的云原生软件共同运行。每个微服务都侧重于一个小而具体的问题。微服务是松散耦合的，这意味着它们是相互通信的独立软件组件。开发人员通过处理单个微服务来更改应用程序。这样，即使一个微服务出现故障，应用程序仍能继续运行。

    • 服务网格

      • 服务网格是一个软件层，用于处理应用程序中服务之间的所有通信。该层由容器化微服务组成。服务网格提供了监控、记录、跟踪和流量控制等新功能。它独立于每项服务的代码，这使它能够跨网络边界和多个服务管理系统工作。

云原生技术如何使企业受益

受益方式 具体内容
效率提升 1.微服务解耦开发（分工明确，独立部署，快速集成）
2.容器化简化部署（灵活、跨平台）
3.CI/CD 加速交付，快速响应市场变化，缩短产品的上市时间
降低成本 1.优化资源利用率，按需缩减计算资源，减少硬件与运维成本
2.声明式 API 描述期望状态而非步骤细节，提高自动化的可操作性，简化自动化流程
3.自动化减少人力成本
系统稳定 1.服务无状态与可替换性，强调不可变基础设施，构建更加健壮和可靠的系统，降低故障停机的概率
2.服务网格轻松实现蓝绿发布、金丝雀发布等
3.成熟稳定的监控告警体系

云原生岗位技能分析

  • 通过部分岗位招聘要求明细分析，需要掌握的前十个框架以及掌握程度分析如下
  1. Kubernetes (K8s)：需要精通Kubernetes的基本工作原理，包括调度器、容器运行时、容器网络等。熟悉Kubernetes的API server、kubectl/kubebuilder等，有源码级别的系统理解和二次开发经验者优先。
  2. Docker：熟悉Docker的生态体系，包括容器化技术、Dockerfile编写、镜像管理等，有容器平台建设和运维经验者优先。
  3. Go：熟练掌握Golang编程语言，有大型分布式、高并发、高性能、高可用系统的设计开发经验。
  4. Python：熟练掌握Python编程语言，了解Python在AI训练框架如Tensorflow/Pytorch中的应用。
  5. C++：掌握C++编程语言，有使用C++进行大规模训练实践经验者优先。
  6. Istio：熟悉Istio作为服务网格框架，了解其工作原理和在云原生架构中的应用。
  7. Prometheus：熟悉Prometheus用于监控容器系统，了解其存储机制、性能优化等。
  8. Helm：熟悉Helm作为Kubernetes的包管理工具，用于应用的部署和管理。
  9. etcd：了解etcd作为分布式键值存储系统，常用于Kubernetes集群中存储配置数据。
  10. MLFlow / Kubeflow：熟悉机器学习平台架构，如MLFlow或Kubeflow，有大规模训练实践经验者优先。

掌握程度方面，对于Kubernetes和Docker，需要深入的理解和实践经验，包括系统设计、运维管理、故障排查等。对于编程语言Go和Python，需要扎实掌握的程度，能够进行高性能、高可用系统的设计和开发。对于Istio、Prometheus、Helm框架，需要有实际的使用经验和理解其在云原生架构中的作用。对于MLFlow和Kubeflow，了解机器学习平台领域的应用，有实践经验者优先。

此外，对于云计算、云原生技术、分布式系统、微服务架构等有全面的认知和实践经验，能够独立解决问题，具备良好的学习能力和团队合作精神。

  • 将热门的云原生岗位进行数据分析，可以总结得出：
    • Go语言是云原生开发必备技能
    • 云原生框架必须掌握：
      • K8S（服务调度）
      • Docker（服务部署）
      • Istio（微服务管理）
      • Prometheus（服务监控）
      • Helm（服务编排）


云原生技能学习路线

  1. 学习Dokcer，完成容器的构建、部署、推送
  2. 学习K8S，完成服务的基本编排和微服务集群调度
  3. 学习Helm，完成复杂的业务编排
  4. 学习Istio，完成微服务的流量管理
  5. 学习这些技术栈，需要结合项目贯穿，所以我们会通过Go语言项目实战，并且结合Prometheus贯穿整个学习的流程
