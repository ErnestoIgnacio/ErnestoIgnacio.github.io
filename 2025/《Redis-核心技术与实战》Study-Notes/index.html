这是笔者学习极客时间专栏《Redis 核心技术与实战》的学习笔记，整理了该专栏的核心知识点，以便记忆、复习、查漏补缺


开篇词 (1讲)

开篇词 | 这样学Redis，才能技高一筹

概述

  • 为什么懂得了一个个技术点，却依然用不好 Redis？
    • 只关注零散的技术点，没有建立起一套完整的知识框架，缺乏系统观
  • 在解决问题时，拥有了系统观，就意味着你能有依据、有章法地定位和解决问题
  • 如何高效地形成系统观？
    • 抓住主线，绘制一幅全景知识图

Redis 知识全景图

两大维度

  • 系统维度
    • 需要了解 Redis 的各项关键技术的设计原理，为判断和推理问题打下坚实的基础
    • 还能从中掌握一些优雅的系统设计规范，例如 run-to-complete 模型、epoll 网络模型，这些可以应用到你后续的系统开发实践中
  • 应用维度
    • 作者建议按照两种方式学习: “应用场景驱动”和“典型案例驱动”，一个是“面”的梳理，一个是“点”的掌握
    • 典型案例驱动
      • 重点解读一些对 Redis 的“三高”特性影响较大的使用案例

Redis 作为庞大的键值数据库，遍地都是知识，怎么能快速地知道该学哪些呢？从三大主线入手

三大主线

  • 高性能主线：包括线程模型、数据结构、持久化、网络框架；
  • 高可靠主线：包括主从复制、哨兵机制；
  • 高可扩展主线：数据分片、负载均衡

问题 –> 主线 –> 技术点


课程是如何设计的？

  • 基础篇：打破技术点之间的壁垒，带你建立网状知识结构
    • 抓住重点，理解框架
  • 实践篇：场景和案例驱动，取人之长，梳理出一套属于你自己的“武林秘籍”
    • 以“场景”和“案例”作为驱动
    • 案例
      • 介绍数据结构的合理使用、避免请求阻塞和抖动、避免内存竞争和提升内存使用效率的关键技巧
    • 场景
      • 重点介绍缓存和集群两大场景，会重点讲解缓存基本原理及淘汰策略，还有雪崩、穿透、污染等异常情况；对于集群来说，我会围绕集群方案优化、数据一致性、高并发访问等问题，和你聊聊可行的解决方案
  • 未来篇：具有前瞻性，解锁新特性
    • 了解Redis新特性，对 Redis 的最新探索，了解 Redis 的发展路线图



基础篇 (10讲)

01 | 基本架构：一个键值数据库包含什么？

概述

  • 更好的学习方式就是先建立起“系统观”
    • 如果我们想要深入理解和优化 Redis，就必须要对它的总体架构和关键模块有一个全局的认知

从SimpleKV来分析：具有关键组件的键值数据库架构
