数据库 vs Excel

已经有了电子表格，为什么需要数据库

  • 数据量对比
    • Excel 2003 之前最大行数是 65536 行，Excel 2007 之后最大行数是 1048576 行
    • 数据库理论上没有行数上限
    • 单机数据库若行数太多遇到性能问题，可以通过分库分表等技术解决
  • 结构化查询
    • 数据库有完备的结构化查询语言（SQL）
    • Excel也有结构化查询的功能（Microsoft Query），Excel结构化查询功能不如数据库强大
  • 服务化
    • Excel是文件级别的，直接面向终端用户
    • 数据库面向软件，提供软件接口
  • 事务
    • Excel没有事务，无法做到不同人的工作同时进行
    • 数据库事务是关系型数据库的核心优势
  • 分布式
    • Excel天生是单体的，面向文件的
    • 数据库具有主备复制、高可用、分布式等形态
  • 总结
    • Excel 面向个人，以文件为基础，处理的数据量有限，功能有限，拓展性差
    • 数据库面向软件，接口，处理数据量大，功能强大，事务支持，可拓展性好

MySQL的架构

  • MySQL的架构中，体现了分层架构，管道-过滤器架构，微核架构
  • 软件工程当中有很多经典的架构设计，大型软件往往不是使用单一的架构设计，而是多种混合
  • 研究问题要有清晰的视野，分清楚微观和宏观
  • 理论要灵活实践，不要死读书


客户端是怎样连接MySQL数据库的

TCP/IP连接报文可以作为其他C/S架构的参考

其他连接方式均限于本机连接，使用范围有限。

TCP/IP连接（最常用的连接方式）

  • 三次握手建立TCP连接

  • 认证连接

    • 服务端 → 客户端：发送握手初始化包
    • 客户端 → 服务端：发送验证
    • 服务端 → 客户端：认证结果消息

  • 认证通过之后，客户端开始与服务端之间交互

    • MySQL TCP通讯协议 —— 命令执行
      • 客户端 → 服务端：发送命令包（Command Packet）
      • 服务端 → 客户端：发送回应包

  • 断开MySQL连接

    • 客户端 → 服务器：发送退出命令包

  • 四次握手断开TCP连接

  • MySQL TCP报文格式

    • 消息头：3字节报文长度 + 1字节序号
    • 消息体：1字节指令 + 其余为参数
    • 指令举例：切换数据库（0x02）、查询命令（0x03）

命名管道

  • 同一台服务器通讯（Windows）
  • 命名管道开启方式：--enable-named-pipe

共享内存

  • 服务端配置：--shared-memory
  • 客户端配置：--protocol=memory

UNIX域套接字

  • 服务端配置：--socket=/tmp/mysql.sock
  • 客户端配置：-S /tmp/mysql.sock


一个SQL语句是怎样执行的

总结

  • SQL 语句的执行过程涉及 MySQL 的几乎所有模块：一个 SQL 语句按照：分析 → 优化 → 执行 → 落盘 的步骤执行
  • MySQL 8.0 之后已停用缓存功能
  • 不同存储引擎的执行方法不同

连接器

  • 起一个监听，连接客户端的请求

（查询）缓存

  • 之前执行过的语句会以 KV（键值对）形式缓存在内存中
  • 查询前会先查找是否有相同语句的缓存
  • 不推荐使用缓存：数据表一旦修改，会清除所有相关缓存
  • MySQL 8.0 之后已移除缓存功能

分析器

  • 分析器的作用是理解你要“干什么”
  • 先做词法分析，识别 SQL 语句中的关键字
  • 再做句法分析，判断 SQL 语句是否符合语法规则

优化器

  • 优化器的作用是知道“怎么做”
  • 主要工作是决定如何使用索引，以提高查询效率

执行器

  • 执行器的主要工作是校验权限、调用存储引擎
  • 首先校验用户对目标数据是否有权限
  • 以行为粒度调用存储引擎执行 SQL
  • 如果没有索引，执行器会逐行扫描所有数据

存储引擎

  • 存储引擎的任务是将执行器的指令落实到数据文件上
  • 不同存储引擎的原理和执行方式差异很大


MySQL有哪些存储引擎（四种常见的 MySQL 存储引擎）

MyISAM

对查询效率要求非常高的场景可考虑 MyISAM

  • MySQL 5.5.5 之前的默认存储引擎
  • 插入数据快，空间利用率高
  • 不支持事务

InnoDB

目前最主流的存储引擎，适合各种互联网业务

  • MySQL 5.5.5 之后的默认存储引擎
  • 支持事务、外键
  • 支持崩溃修复能力和并发控制

Memory

临时表可考虑使用 Memory

  • 所有数据存储在内存中，速度快
  • 数据安全性差（重启后数据丢失）

Archive

日志信息归档可考虑使用 Archive

  • 数据压缩，空间利用率高
  • 插入速度快
  • 不支持索引，查询性能差
