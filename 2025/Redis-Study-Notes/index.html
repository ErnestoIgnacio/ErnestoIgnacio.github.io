Introduction：这篇博客是笔者长期学习Redis的学习笔记，包含了Redis安装、使用、优化、运维、架构设计等各个层面的核心知识点总结

Origin：笔者想把Redi的核心知识点做一个系统梳理，能够在软件开发者的角度彻底理解Redis的工作原理以及实战使用，同时查漏补缺


Redis介绍

Redis简介与功能特性

  • Redis 英文全称是 Remote Dictionary Server
  • Redis 是完全开源的，使用 ANSI C 语言编写，遵守 BSD 协议，是一个高性能的 Key-Value 数据库
  • Redis 提供了丰富的数据结构，例如 String、 Hash、 List、Set、SortedSet 等等
  • Redis 的数据是存在内存中的，但 Redis 也可以通过定期策略或者手动操作进行持久化数据
  • Redis 广泛应用于缓存、分布式锁等多种场景；同时 Redis 支持事务、持久化、LUA 脚本、发布/订阅、缓存淘汰、流技术等多种功能特性
  • Redis 提供了主从模式、Redis Sentinel 和 Redis Cluster 集群架构方案


Redis 适用场景

热点加速/缓存加速

  • 缓存是Redis最主要的功能。作为互联网应用上的热点场景：高并发下的数据加载

分布式会话/共享会话

  • 使用 Redis 将用户的 Session 进行集中管理，每次用户更新或者查询登录信息都直接从 Redis 中集中获取
  • （一个分布式 Web 服务将用户的 Session 信息保存在各自服务器，如果节点故障或者是用户刷新一次可能就需要重新登录，这样显然有问题）

排行榜场景

  • Redis 提供的zset 数据类型能够快速实现这些复杂的排行榜（如电商网站的月度销量排行榜、社交 APP 的礼物排行榜、小程序的投票排行榜等等）

分布式计数器/集群计数器

  • 例如浏览数量、播放数量，为了保证数据实时效，每次浏览都得给+1，并发量高时如果每次都请求数据库操作无疑是种挑战和压力

  • 单机：可以利用原子操作/类型实现计数器

  • 分布式环境：Redis 提供的 incr 命令来实现计数器功能，内存操作，性能非常好


最新消息

  • Redis 列表结构，LPUSH 可以在列表头部插入一个内容 ID 作为关键字，LTRIM 可用来限制列表的数量，这样列表永远为 N 个 ID，无需查询最新的列表，直接根据 ID 去到对应的内容页即可

请求限流

  • 主要用于集群限流

分布式锁实现

  • 分布式技术带来的技术挑战是对同一个资源的并发访问，如全局 ID、减库存、秒杀等场景，并发量不大的场景可以使用数据库的悲观锁来实现，但在高并发场景中，利用数据库锁来控制资源的并发访问性能极低，我们可以利用 Redis 的 setnx 功能来编写分布式的锁


Redis vs Memcached

维度 Redis Memcached
定位 内存数据结构服务器，支持丰富功能（缓存 + 数据结构 + 消息队列 + 模块） 轻量级分布式内存缓存，专注高效 KV 缓存
数据类型 字符串、哈希、列表、集合、有序集合、位图、HyperLogLog、Streams、地理位置等 仅支持 key → value（blob），有限的 incr/decr、CAS
持久化 支持 RDB 快照、AOF 日志，可恢复数据 不支持，重启即丢失
并发模型 单线程执行命令（Redis 6+ 支持 I/O 多线程）；需多实例或 Cluster 利用多核 多线程并发处理，天然能用多核，吞吐高
缓存淘汰策略 多种策略：LRU/LFU/TTL/随机/不驱逐等，粒度灵活 基于 slab 的近似 LRU，策略单一
内存管理 对象有额外开销，但支持小对象优化（ziplist 等）；灵活但更占内存 slab 分配器，内存利用率高，对大量小对象更省
可扩展性 支持 Redis Cluster（分片）、Sentinel（HA）、复制；模块化扩展 没有内建分布式和 HA，通常用客户端一致性哈希或代理（mcrouter）
高可用/复制 内置主从复制、Sentinel 故障转移、Cluster 自动分片 无内建，需应用层或外部代理实现
安全 支持 ACL、认证、TLS（6.0+） 协议简单，支持 SASL（需启用），TLS 支持有限
扩展能力 Lua 脚本、事务、发布/订阅、Stream、模块（RedisSearch、RedisJSON、Graph 等） 无扩展机制
生态与工具 丰富（redis-cli、RedisInsight、redis-benchmark），多云提供托管服务 工具少（memcached-tool），但 mcrouter、twemproxy 可用；也有云托管
典型使用场景 会话存储、排行榜、计数器、消息队列、发布订阅、复杂数据结构缓存 页面缓存、热点对象缓存、会话缓存（非持久化）、极高并发 KV 缓存
运维复杂度 功能丰富但配置/运维复杂（持久化、Cluster、备份） 部署简单，节点可直接扩展，运维轻量
性能特点 单核低延迟，复杂结构操作高效；横向扩展依赖 Cluster/多实例 多核并发吞吐强大，纯 KV 场景性能通常更高


Redis vs MySQL

  • Redis 和 MySQL 不是替代关系，而是互补关系
  • 常见架构：
    • MySQL 作为持久化存储
    • Redis 作为缓存层，存储热点数据，提升读写性能，缓解数据库压力
维度 Redis MySQL
定位 内存型键值/数据结构存储，主要用于缓存与高性能场景 关系型数据库，主要用于持久化存储和复杂查询
数据存储模型 Key-Value + 丰富数据结构（String、Hash、List、Set、ZSet、Stream 等） 表、行、列，支持复杂关系模型
存储介质 内存为主（可选持久化到磁盘） 磁盘为主（InnoDB 缓存页 + redo log 优化）
性能 读写速度极快（微秒级），高并发能力强 读写性能较慢（毫秒级），尤其在高并发下需要优化
持久化 可选（RDB 快照、AOF 日志）；可关闭以获得极致性能 强一致持久化，数据安全性高
事务支持 简单事务（MULTI/EXEC），支持 Lua 脚本原子执行 完整的 ACID 事务支持
查询能力 基于 key 的高效查找，部分数据结构支持 O(1)/O(logN) 操作 强大的 SQL 查询，支持 JOIN、聚合、索引优化
扩展性 支持 Cluster 分片与复制，适合水平扩展 主从复制、分库分表、Sharding 方案，扩展复杂
数据一致性 弱一致性（最终一致，依赖应用保证） 强一致性（事务 + WAL）
高可用/集群 Sentinel、Cluster 原生支持 MGR、主从复制、Galera Cluster 等方案
典型应用场景 缓存层、会话管理、排行榜、消息队列、实时计数器 核心业务数据存储、事务处理、复杂查询
优缺点总结 优点：高性能、灵活数据结构；缺点：内存开销大、查询能力弱 优点：数据安全、查询强大；缺点：性能受限、扩展复杂



Redis安装

安装前置条件

操作系统说明

  • Redis 是用 ANSI C 编写的，可以在大多数 POSIX 系统上运行，比如 Linux、*BSD 和 Mac OS X，没有外部依赖
  • Linux 和 OS X 是 Redis 开发和测试最多的两个操作系统
  • 官方推荐使用 Linux 部署，Windows 版本没有官方支持

操作系统参数设置（使用root用户设置）

  • 在 /etc/sysctl.conf 中设置 vm.overcommit_memory = 1，用 sysctl vm.overcommit_memory=1 立即生效

    • 0：内核将检查是否有足够的内存分配给程序，如果没有则申请失败，并把错误返回给应用进程。而在 Redis 中这个错误就会表现为“Cannot allocate memory”，然后触发 OOM
    • 1：表示内核允许超量使用内存直到用完为止
    • 2：表示内核决不超量使用内存，即系统整个内存空间不能超过 swap+50%的 RAM 值，50%是 overcommit_ratio 默认值，此参数支持修改

  • 配置大内存页面，echo never > /sys/kernel/mm/transparent_hugepage/enabled，并同过下面命令进行永久生效

  • 关闭交换 swap 内存，swapoff -a，并通过 vim /etc/fstab 将交换内存注释掉(确保物理机有够用的物理内存)

安装单机多实例

概述

  • Redis单机多实例的好处？
    • Redis 默认是 单线程 处理请求，单实例只能利用 一个 CPU 核心
    • 如果机器有 8 核 CPU，跑 1 个 Redis 就浪费了 CPU；跑 8 个 Redis，可以让每个实例绑定到不同核心，提升整体吞吐量

单机多实例的安装

当前已经有一台Redis实例的情况下，安装多实例

    Redis数据类型

    Redis 数据类型一览表（最新版本）

    数据类型 存储结构 使用场景 常用命令 特征说明
    String（字符串） 二进制安全字符串（最大 512MB） 缓存对象、计数器、分布式锁、JSON 文本 SET GET INCR DECR APPEND 最基础的数据类型，可以存储文本、数字、二进制，支持整型/浮点运算
    List（列表） 双向链表或压缩列表 消息队列、任务队列、按时间顺序存储数据 LPUSH RPUSH LPOP RPOP LRANGE 有序，可在两端插入/弹出元素，适合队列/栈操作
    Hash（哈希） 类似 Map<K,V>，存储字段和值 存储对象（如用户信息、商品属性） HSET HGET HDEL HGETALL 类似于小型数据库表，适合存储结构化对象
    Set（集合） 无序且唯一元素集合 去重、标签、共同好友计算 SADD SREM SISMEMBER SUNION SINTER 元素自动去重，支持集合间运算（交并差）
    Sorted Set（有序集合 ZSet） 每个元素带有一个分数 score，按分数排序 排行榜、优先队列、带权重排序 ZADD ZRANGE ZREM ZINCRBY ZRANK 元素唯一但分数可重复，支持按分数排序和范围查询
    Stream（流） 消息流结构（类似 Kafka） 日志系统、消息队列、事件订阅 XADD XREAD XGROUP XREADGROUP 持久化消息队列，支持消费者组，适合日志/事件流
    Bitmap（位图） 位操作，底层基于 String 用户签到、活跃统计、状态记录 SETBIT GETBIT BITCOUNT BITOP 高效存储布尔状态，一个 bit 代表一个用户/状态
    HyperLogLog 基于概率的数据结构（12KB 固定内存） 大规模基数统计（UV 去重） PFADD PFCOUNT PFMERGE 内存占用极小，统计结果是近似值（误差约 0.81%）
    Geospatial（地理空间） 基于 Sorted Set 实现 存储地理位置、附近的人/店 GEOADD GEODIST GEORADIUS 支持地理坐标存储、范围查询、距离计算
    JSON（模块扩展） RedisJSON 提供 存储和查询 JSON 文档 JSON.SET JSON.GET JSON.DEL 原生支持 JSON 操作，支持路径查询和修改
    TimeSeries（时间序列，模块） RedisTimeSeries 提供 IoT 数据、监控数据、时序指标 TS.ADD TS.RANGE TS.MRANGE 高效存储和查询时间序列，支持聚合与压缩
    Bloom Filter（布隆过滤器，模块） RedisBloom 提供 判断元素是否存在（防止缓存穿透） BF.ADD BF.EXISTS 占用空间小，支持高效判定，存在一定误判率
