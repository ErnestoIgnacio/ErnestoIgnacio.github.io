数据库介绍

数据库定义

Database

  • 数据库（Database）指存储在计算机内的数据集合（数据库就是存储数据的地方）。数据库实际上就是一个文件集合，是一个存储数据的仓库。数据库是按照特定的格式把数据存储起来，用户可以对存储的数据进行增删改查操作

RDBMS

  • 数据库管理系统（RDBMS：Relational Database Management System）是数据库系统的核心软件，是用于存储、管理和组织结构化数据的电子系统。它是位于用户与操作系统之间的数据管理软件，用于建立、使用和维护数据库。它的主要功能包括数据定义、数据操作、数据库的运行管理、数据库的建立和维护等几个方面。

  • 数据库管理系统允许用户以更有效的方式存储和检索数据，并提供了数据的安全性、完整性和一致性。

  • 我们也可以将数据存储在文件中，但是在文件中读写数据速度相对较慢。所以，现在我们使用关系型数据库管理系统（RDBMS：Relational Database Management System）来存储和管理大数据量。我们常说某某数据库，其实实质上是某某数据库管理系统。



数据库分类

按关系分类

根据表与表之间的关系主要分为两类：关系型数据库和非关系型数据库

关系型数据库

  • 关系型数据库(Relational Database，RDS)是现在应用最广泛的数据库，它是建立在关系模型基础上的数据库，借助于集合代数等数学概念和方法来处理数据库中的数据。
  • 关系型数据库在 1969 年诞生，可谓历史悠久。和 Excel 工作表一样，关系型数据库也采用由行和列组成的二维表来管理数据，所以简单易懂。
  • 同时，它还使用 SQL（Structured Query Language，结构化查询语言）对数据进行操作。简单说，关系型数据库是由多张能互相连接的表组成的数据库。
  • 常见的关系数据库有Oracle、MySQL、SQL Server、PostgreSQL等。

非关系型数据库

  • 非关系型数据库又被称为 NoSQL（Not Only SQL )，意为不仅仅是 SQL。通常指数据以对象的形式存储在数据库中，而对象之间的关系通过每个对象自身的属性来决定。非关系型数据库种类较多，常见的有下面几种：
    • 键值存储（Key-Value Store，KVS）数据库：redis
    • 面向文档（Document-Oriented）数据库：MongoDB
    • 图形数据库：Neo4j
    • 搜索引擎数据库：Elasticsearch
    • 时序数据库:InfluxDB

按功能分类

根据数据库侧重的功能分类，大概可以分为三种类型数据库:

OLTP:（on-line transaction processing）联机事务处理

  • 侧重于对数据的增删改，关注数据的实时性，并且有事务管理，对于数据的一致性也有要求，数据量一般不大
  • 典型的数据库是关系型行式数据库，例如MySQL，POSTSQL，Oracle等

OLAP:（on-line analytical processing）联机分析处理

  • 侧重于数据的分析，可能只关注数据的最终一致性，对实时性要求不高，一般是海量的数据
  • 典型的一般是分布式的列式存储数据库，例如clickhouse，hbase，hive/sparksql+hdfs等

HTAP（同时支持 OLTP 和 OLAP 场景）

  • 需要创新的计算存储框架，在一份数据上保证事务的同时支持实时分析，省去费时的 ETL 过程，例如：TIDB，OceanBase等
  • TiDB是PingCAP公司自主设计、研发的开源分布式关系型数据库
  • OceanBase是阿里巴巴金融级分布式关系数据库


数据库专业术语

  • Database：指存储在计算机上的数据集合。它可以包括一个或多个表，每个表可以包括多个行和列，用于存储数据
  • Table：指数据库中的一个独立的数据存储结构，它由若干个列组成，每个列存储一个特定类型的数据。在一个数据库中的表看起来像一个简单的电子表格
  • Column：指表中的一列，用于存储相同类型的数据。表由一个或多个列组成的
  • Row：指表中的一行，包含一组相关的数据。表中的数据是按行存储的
  • Primary Key：指在表中唯一标识每个行的一列或一组列，它用于确保表中每个行的唯一性。一个表中只能包含一个主键，主键列的值不能为NULL
  • Foreign Key：用于建立表与表之间的关系。外键列存储另一个表中的主键值
  • Index：指用于提高查询速度的数据结构，类似于书籍的目录。它可以加速数据的查找和排序
  • View：指一个虚拟的表，它由查询语句生成，不包含实际的数据
  • Stored Procedure：指预先编译的一组SQL语句，可重复执行，用于简化复杂的数据操作
  • Transaction：指一组相关的数据库操作，必须完全执行或完全撤销
  • Trigger：指在特定条件下自动执行的一组SQL语句，用于维护数据的完整性和一致性。例如，当数据被插入到一张表中时，触发器可以自动更新另一张表中的相应数据
  • Backup：指对数据库进行定期备份的过程，以确保数据安全性和可恢复性



MySQL简介数据库介绍

MySQL数据库介绍

  • MySQL 是最流行的数据库之一，是一个免费开源的关系型数据库管理系统。MySQL 由瑞典 MySQL AB 公司开发，目前属于 Oracle 公司。MySQL 适合中小型应用，被个人用户以及中小企业青睐
  • MySQL 的命名机制由 3 个数字和 1 个后缀组成，例如 mysql-8.0.33：
    • 第 1 个数字“8”是主版本号，用于描述文件的格式，所有版本 8 的发行版都有相同的文件夹格式
    • 第 2 个数字“0”是发行级别，主版本号和发行级别组合在一起便构成了发行序列号
    • 第 3 个数字“33”是在此发行系列的版本号，随每次新发行的版本递增。通常选择已经发行的最新版本


MySQL的优点

  • 开源：MySQL 是开放源代码的数据库，任何人都可以获取该数据库的源代码。同时拥有庞大的开发者社区，提供了大量的技术支持和资源
  • 免费：MySQL 数据库是一个自由软件，任何人都可以从 MySQL 的官方网站上下载该软件，这些社区版本的 MySQL 都是免费试用的，即使是需要付费的附加功能，其价格也是很便宜的。相对于 Oracle、DB2 和 SQL Server 这些价格昂贵的商业软件，MySQL 具有绝对的价格优势
  • 简单：MySQL 是一个单进程多线程 SQL 数据库服务器。它能够快速、有效和安全的处理大量的数据。相对于 Oracle 等数据库来说，MySQL 的使用是非常简单的。MySQL 主要目标是快速、健壮和易用。稍微有IT背景的技术人员都可以无师自通地参照文档安装运行和使用MySQL，几乎没有什么门槛。MySQL还图形化界面工具，使数据库管理和操作变得简便
  • 稳定可靠：MySQL经过长期的发展和测试，表现出良好的稳定性和可靠性，能够处理高并发和大规模的数据
  • 高可用：MySQL从3.23.15这个版本开始，支持了replication，可以帮助MySQL使用者搭建Master-Slave的架构。把数据准实时的从一个实例同步到另一个实例
  • 存储引擎：MySQL不同于其他多数数据库之处是它对插件式存储引擎的支持，这是一个开放的设计，有点兼容并包，海纳百川的感觉
  • 跨平台性：MySQL 不仅可以在 Windows 系列的操作系统上运行，还可以在 UNIX、Linux 和 Mac OS 等操作系统上运行。因为很多网站都选择 UNIX、Linux 作为网站的服务器，所以 MySQL 的跨平台性保证了其在 Web 应用方面的优势
  • 流行度：在数据库领域有个排行榜，叫DB Engines，MySQL是排在第二位，是开源数据库的第一位


MySQL发展历程

  • MySQL的发展历程可以追溯到20世纪90年代初，它最早由Michael Widenius和David Axmark开发，并于1995年首次发布
  • 创业时期（1995年 - 1998年）
    • MySQL AB成立，开始开发MySQL数据库
    • 1995年，第一个预览版面世
    • 1998年，MySQL 3.21发布，此版本是MySQL社区版中功能最为丰富、历史最为悠久的版本之一
  • 持续发展期（1999年 - 2005年）
    • 1999年，MySQL AB推出了商业版MySQL Enterprise
    • 2000年，MySQL 3.23发布，MySQL数据库正式进入企业市场
    • 2003年，MySQL AB推出了MySQL可插拔存储引擎架构
    • 2005年，MySQL 5.0发布，支持储存过程、触发器、视图、子查询等高级特性，成为最流行的MySQL版本
  • 突破发展期（2008年 - 2010年）
    • 2008年，Sun Microsystems收购了MySQL AB，成为MySQL的母公司
    • 2010年，Oracle Corporation收购Sun Microsystems，MySQL成为Oracle的一部分
  • 优化和扩展期（2010年 - 至今）
    • 2010年，MySQL AB推出了MySQL Cluster软件，实现了“ACID”语义的分布式数据库集群技术
    • 2013年，MySQL 5.6发布，支持NoSQL接口，增强性能和可靠性
    • 2015年，MySQL 5.7发布，支持JSON列类型和在线DDL操作，改进了查询优化器和复制架构
    • 2018年，MySQL8.0版本发布，集成InnoDB引擎，废弃MyISAM引擎。增加了数百项功能新特性，重构了SQL解析器，在性能和安全性上越来越向商业数据库靠拢
    • 2023年07月18号，MySQL 8.1.0发布
    • 2023年10月31号，MySQL5.7停服，意味着Oracle 将不再提供此版本数据库的更新，而8.0的支持将持续到2026年


MySQL版本分类

  • MySQL的版本分为两个主要分支：
    • MySQL Community Edition
      • Community Edition是免费的开源版本，不提供技术支持
    • MySQL Enterprise Edition
      • Enterprise Edition是商业版本，提供高级功能、技术支持和额外的工具，例如EnterpriseBackup、EnterpriseMonitor等
  • 除了MySQL官方版本，还有一些分支版本：
    • MariaDB（MySQL作者开发，版本领先于MySQL）
    • Percona（MySQL运维开发，版本与MySQL保持一致，与MySQL完全兼容，它的存储引擎是XtraDB。XtraDB 是 InnoDB 存储引擎的增强版，使用是透明的。发布了配套的XtraBackup、toolkit等工具）

（2）创建（不能登录的）运行 MySQL 的用户

  • 为什么需要单独创建运行 MySQL 的用户

    • 用于文件权限控制和进程归属，让 MySQL 有自己的文件权限空间
      • 因为 Linux 文件系统用 UID/GID 来判断访问权限，MySQL 启动后要访问：数据文件、日志、二进制程序文件；这些文件都需要属于 mysql:mysql，MySQL 服务启动时才能正确读写

  • 为什么要禁止登录

    • 防止被黑客利用
      • 如果 mysql 用户可以登录系统，就意味着：
        • 任何拿到数据库权限的人（例如能执行 SELECT ... INTO OUTFILE），或者攻破 MySQL 服务的人都可以直接切换成 mysql 用户，执行系统命令！这等于从数据库漏洞直接升级为系统权限漏洞
    • 让 mysql 用户“不可登录”可以有效防止：
      • SSH 登录；
      • 控制台登录；
      • 使用 su - mysql 进入交互 shell。
    • 一种通用安全规范，因为这些用户：
      • 只需要访问它们自己的文件；
      • 不需要也不应该有 shell 登录权限。
    • 防止误操作或越权，设为不可登录，就能避免人为操作风险
      • 如果 mysql 用户可以登录：
        • 误删 /data/mysql 文件；
        • 修改错误的配置；
        • 启动命令行执行危险脚本；

（3）规划数据目录，准备 my.cnf 参数文件

  • 不同版本对数据目录的规划可能有所区别

*准备配置 my.cnf 参数文件

  • 在 MySQL 中，参数的初始化是通过参数文件来进行设置，如果不设置参数文件，MySQL 就按照系统中所有参数的默认值来进行启动

  • 在 Linux 上，参数文件可以被放在多个位置，数据库启动的时候将按照不同的顺序来搜索，如果在多个位置都有参数文件，则搜索顺序靠后的文件中的参数将覆盖靠前的参数。

  • 准备 my.cnf 参数文件**（为了避免参数覆盖，最好是删除可能已经存在的参数文件）**

    [mysqld]下的user=mysql 表示指定 MySQL 服务器进程 (mysqld) 以哪个系统用户身份运行，当 MySQL 服务启动时（无论是手动启动还是通过 systemd/service 启动），它会自动切换为系统用户 mysql 来运行数据库进程。如果使用了该参数，则需要提前设置数据目录的权限为mysql:mysql

  • 最佳实践

  • 初始化的参数详解

    --user=mysql 的作用是什么？

    在初始化时，切换为系统用户 mysql 去创建这些文件

    • 文件属主是：mysql:mysql
    • 权限符合 MySQL 后续运行需求
    • 启动 MySQL 服务时不会有权限问题

    如果不加 --user=mysql 会发生什么

    • 假设你是 root 用户 执行命令：
      • 初始化会以 root 身份创建所有文件；
      • 所有文件的属主、属组都是 root:root；
      • 如果my.cnf文件的[mysqld]下配置了user=mysql，且没有设置数据目录的权限为mysql:mysql将会启动失败（需要手动修复chown -R mysql:mysql /data/mysql3306然后再进行初始化）
      • MySQL 启动时（以 mysql 用户运行）将无法访问这些文件。

（5）启动数据库服务

  • 方式一：mysqld

    • mysqld是一个可执行命令，也是服务器端程序，启动这个程序就相当于启动了MySQL服务器端的进程。但这个命令不常用，常用mysqld_safe命令

  • 方式二：mysqld_safe（最佳实践）

    • mysqld_safe是一个启动脚本，间接引用mysqld。在启动mysqld_safe脚本时，启动MySQL服务器进程，同时会启动一个守护进程，作用是监控mysqld，如mysqld服务挂了后，会立即重启一个mysqld服务。mysqld_safe相当于mysqld的一个看门狗进程。
    • 另外，mysqld_safe启动方式也会把运行过程的报错日志和其它一些诊断信息输出到错误日志中，这样方便我们排查解决问题。这个启动方式是最常用的方式

  • 方式三：mysql.server

    • mysql.server也是一个启动脚本，它会间接的调用mysqld_safe，mysql.server 文件其实是一个链接文件，它的实际文件是 ../support-files/mysql.server

参数管理

  • 参数类型可以分为服务器参数（静态参数、动态参数）、服务器状态参数（各种运行时的统计信息）

  • 服务器参数：

    • 静态参数：在 MySQL服务运行的过程中不能修改，即只读，只能通过 my.cnf参数文件修改，重启生效
    • 动态参数：可以在mysql服务运行的过程中进行修改，即时生效

    可以通过 set 命令对动态参数进行修改，通过@@global和@@session来指定是对当前会话进行修改还是对所有会话进行修改

    注意：动态设置参数在服务器重启后会失效。如果要保留设置，必须同时修改配置文件

  • 服务器状态参数：

    • MySQL中维护了很多关于程序运行状态的参数，它们被称为 状态参数 。由于 状态参数 是用来显示服务器程序运行状况的，所以它们的值是由服务器程序自己来设置，我们是不能设置的。与 系统参数 类似， 状态参数也分为 GLOBAL 和 SESSION 范围
    • 参数设置方式：
      • 配置文件： MySQL 有个配置文件(my.cnf)，我们可以设置数据目录位置、共享内存大小以及其他参数
      • 启动脚本： 在启动mysql时，直接将参数传递给 mysqld 进程
      • 使用 set 命令 (支持设置动态参数)：临时生效，如需永久生效需要修改配置文件

注意：设置全局变量，对当前会话和其他已存在会话的值不生效不受。新建会话则会生效。如果客户端建立的是长连接，请记住这一点。

参数持久化

MySQL 5.7 之前我们修改参数后，需要将其手动写入到配置文件中，否则重启后又恢复原有的配置，在 8.0 中可以在 MySQL 客户端直接将参数持久化，节省在服务器操作的步骤。

MySQL 8.0 版本支持在线修改全局参数并持久化，通过加上 PERSIST 关键字，可以将修改的参数持久化到新的配置文件（mysqld-auto.cnf）中，重启 MySQL 时，可以从该配置文件获取到最新的配置参数！

启用这个功能，使用特定的语法 SET PERSIST 来设定任意可动态修改的全局变量！

  • SET PERSIST 语句可以修改内存中变量的值，并且将修改后的值写⼊数据⽬录中的 mysqld-auto.cnf 中。

  • SET PERSIST_ONLY 语句不会修改内存中变量的值，只是将修改后的值写⼊数据⽬录中的 mysqld-auto.cnf 中，重启生效。

参数设置

  • MySQL 8.0有六百多个系统参数，innodb存储引擎也有自己独立的参数

[mysql]

  • 这部分参数由 mysql 命令行客户端读取
参数值 参数用途
port = 3306 指定客户端连接的端口
socket = /tmp/mysql.sock 指定连接socket的位置
auto_rehash 使用tab键进行自动补全
loose-skip-binary-as-hex 在执行 LOAD DATA INFILE 语句时，是否将二进制数据作为十六进制字符串加载到数据库中。如果文件中包含二进制数据，MySQL 默认会将其作为文本字符串加载到数据库中。如果二进制数据中包含了某些特殊字符（例如 NULL 字符），这可能会导致数据加载不完整或格式错误。

注意：当配置auto_rehash参数时，就需要数据库、表、字段信息全部加载到客户端对应的缓存里。这样导致卡顿慢的等问题，间接的给MySQL服务带来负面影响。所以实际运维场景中不建议使用这个参数。

  • 也可用在使用mysql命令行工具是指定：

[client]
